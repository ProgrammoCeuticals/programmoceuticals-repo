## Phase C — Design/UX improvement

- Modernise the visual system and responsive layout.
- Simplify navigation while preserving required pathways.
- Improve readability of financial product information.
- Make contact links and important CTAs easy to find.
- Provide accessible forms with helpful validation.
- Keep savings, loan and membership actions distinct.
- Clearly display approved current product conditions.
- Make content maintainable by the organisation.

## Phase D — Secure application workflows
Only if OSFNG confirms it needs interactive membership/loan applications:
- Define who receives applications and how they are processed.
- Define required fields and documents.
- Add server-side validation and secure document storage.
- Create reference numbers and reliable submission confirmation.
- Define status transitions and who is authorised to change status.
- Apply privacy/security controls and a data-retention policy.
- Never store financial/identity documents in a publicly accessible folder.
- Test form delivery end-to-end before launch.

# 7. Design and technical recommendations (proposed, not actual site content)

The original styling could not be evaluated during this review, so these are redesign recommendations rather than claims about the existing site.

- Obtain original OSFNG logos and approved brand colours.
- Use a professional, trustworthy community-finance visual language, with accessible typography and clear information hierarchy.
- Preserve the organisation's actual product categories.
- Design mobile-first for visitors using low-bandwidth connections.
- Do not use unrelated logos from other organisations sharing “Operation Smile” in their name.
- Use authentic, approved OSFNG/community photos; confirm image rights and consent.
- Keep all product rates, fees and terms in structured content so authorised staff can update them.
- Make the menu/footer consistent on every page.
- Use descriptive page metadata and meaningful alt text.
- Make all forms keyboard-accessible and screen-reader friendly.
- Use server-confirmed form success/error messages only.
- Add a CMS only if OSFNG needs staff to update news/programmes frequently; do not introduce unnecessary backend complexity for static pages.
- Do not build an online banking system, wallet, savings transactions, customer login or loan decision engine unless the organisation requests and specifies it separately.
